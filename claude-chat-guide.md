# Свой сервер для обычного чата с Claude (без Claude Code) — методичка

> **Неофициальная методичка.** Не аффилирована и не одобрена Anthropic — составлена по
> личному опыту эксплуатации прокси/VPN-сервисов на собственном сервере. Используете
> на свой риск, особенно пункты про firewall и аутентификацию прокси.

Это упрощённый вариант [основной методички](README.md) — для тех, кому нужен только
обычный чат на claude.ai в браузере, а не Claude Code/панель разработки. Если не нужен
терминал/кодинг на сервере — не нужен и весь Шаг 4-5 из основной методички. Нужен только
личный прокси/VPN с европейским IP.

## В чём разница с основной методичкой

Там: устанавливаем Claude Code и веб-панель поверх него, заходим в браузере на
свой домен — сам чат физически работает НА сервере.

Здесь: сервер ничего не знает про Claude вообще. Он просто **пробрасывает ваш трафик**
через свой европейский IP — как будто вы физически находитесь в Европе. Дальше открываете
claude.ai как обычно, в любом браузере/приложении, логинитесь как обычно. Сервер тут —
просто труба, а не место, где что-то выполняется.

Это ровно то же самое, что делает VPN — просто свой личный, а не шэренный с тысячами
чужих пользователей (в этом и была вся идея исходного курса: свой стабильный IP вместо
подозрительного публичного VPN-адреса).

**Плюс этого варианта:** сильно проще и быстрее в развёртывании (15-20 минут, не вечер),
не нужен домен и HTTPS-сертификат, не нужно ничего понимать про терминал глубоко.

**Минус:** это just proxy для сети — если хочется ещё и гонять Claude Code/агентов
на сервере в фоне, всё равно понадобится основная методичка.

## Термины

- **Прокси** — сервер-посредник, через который проходит ваш трафик к нужному сайту.
- **SOCKS5** — простой и лёгкий протокол прокси, не шифрует сам по себе трафик
  дополнительно (не нужно — claude.ai и так работает по HTTPS), просто меняет
  видимый сайту IP-адрес.
- **VPN** — то же самое, но для ВСЕГО трафика устройства, а не только браузера, и с
  собственным шифрованием поверх.

## Какой вариант выбрать

| Вариант | Сложность | Что покрывает | Когда выбрать |
|---|---|---|---|
| SOCKS5-прокси | Минимальная | Только браузер (через настройки прокси или расширение) | Нужен только доступ к claude.ai в браузере |
| WireGuard/AmneziaWG (VPN) | Средняя | Всё устройство целиком | Хочется общий VPN, не только под Claude |

Для большинства читателей, которым нужен именно чат — **SOCKS5-прокси** самый быстрый
путь. Ниже — оба варианта.

## TL;DR

```bash
# На сервере:
apt update && apt install -y fail2ban ufw docker.io
ufw allow 22/tcp && ufw allow 1080/tcp && ufw --force enable

docker run -d --name socks5-proxy --restart unless-stopped \
  -p 1080:1080 \
  -e PROXY_USER=myuser \
  -e PROXY_PASSWORD="$(openssl rand -base64 24)" \
  serjs/go-socks5-proxy

docker logs socks5-proxy   # хотя бы убедиться, что контейнер не упал сразу
```

Дальше — FoxyProxy в браузере с адресом сервера, портом 1080 и заданными выше
логином/паролем (посмотреть заданный пароль: `docker inspect socks5-proxy | grep PASSWORD`).

## Вариант А: SOCKS5-прокси (быстрее всего)

### Шаг 1. Купи сервер

Тот же выбор, что и в основной методичке — Webdock (зарубежная карта) или Timeweb
(российская карта). Домен здесь **не обязателен** — можно ходить сразу по IP сервера.
Минимальный тариф (1-2 ГБ RAM) для одного прокси-сервиса более чем достаточен —
это лёгкий процесс, в отличие от Claude Code с панелью.

### Шаг 2. Зайди по SSH и поставь firewall сразу

```bash
ssh root@185.xx.xx.xx
```

Как и в основной методичке — **сразу**, до всего остального, поставьте `fail2ban` и
настройте `ufw` (открыт только 22/SSH и порт прокси, который выберете ниже). Публичный
сервер без этого начинает получать брутфорс-попытки входа с первого дня.

✅ **Проверка шага:** `systemctl status fail2ban` — active (running); `ufw status` —
показывает только нужные порты.

### Шаг 3. Подними SOCKS5-прокси

Проще всего — готовый Docker-образ, поднимается одной командой (если Docker ещё не
стоит — попросите Claude/погуглите "install docker ubuntu", это стандартный шаг):

```bash
docker run -d --name socks5-proxy --restart unless-stopped \
  -p 1080:1080 \
  -e PROXY_USER=myuser \
  -e PROXY_PASSWORD=ОченьДлинныйСлучайныйПароль \
  serjs/go-socks5-proxy
```

Замените `myuser`/пароль на свои — оставлять прокси без пароля нельзя, иначе им
бесплатно воспользуется полинтернета, как только просканирует ваш IP.

Откройте порт в firewall:

```bash
ufw allow 1080/tcp
```

✅ **Проверка шага:**

```bash
docker ps --filter name=socks5-proxy   # Up, не перезапускается по кругу
curl -x socks5://myuser:пароль@127.0.0.1:1080 -I https://claude.ai
```
Если `curl` возвращает любой HTTP-код (а не ошибку соединения) — туннель до claude.ai
физически работает. Cloudflare может ответить страницей проверки браузера на `curl` —
это нормально, реальный браузер её пройдёт автоматически.

### Шаг 4. Настрой браузер на использование прокси

- **Chrome/Firefox напрямую** — не умеют прокси с логином/паролем без расширения.
  Проще всего поставить расширение **FoxyProxy** (Chrome/Firefox) и указать в нём:
  - Тип: SOCKS5
  - Адрес: IP вашего сервера
  - Порт: 1080
  - Логин/пароль: те, что задали выше
- Включаете расширение только когда нужен доступ к claude.ai — остальной трафик
  браузера идёт как обычно.

Открываете claude.ai — сайт видит IP вашего сервера, логинитесь как обычно.

✅ **Проверка шага:** в браузере с включённым FoxyProxy откройте `https://2ip.ru` или
`https://whatismyipaddress.com` — показанный IP должен совпадать с IP вашего сервера,
а не с вашим реальным.

## Вариант Б: полноценный VPN (WireGuard/AmneziaWG)

Если хочется не точечный прокси под один сайт, а обычный VPN на всё устройство:

1. Поднять WireGuard (или AmneziaWG — та же технология, с дополнительной маскировкой
   трафика под обычный HTTPS, полезно если провайдер блокирует VPN-протоколы напрямую).
2. Сгенерировать конфиг клиента (обычно QR-код или файл `.conf`).
3. Установить клиентское приложение WireGuard/AmneziaWG на телефон/компьютер,
   импортировать конфиг, включить.

Это отдельная по объёму тема с большим числом гайдов (например, официальный
`wg-quick` или готовые скрипты вроде `angristan/wireguard-install`) — если нужен именно
этот вариант, попросите Claude Code развернуть его пошагово на сервере, аналогично
Шагу 5 основной методички (одним запросом с задачей "разверни WireGuard-сервер,
сгенерируй мне клиентский конфиг").

✅ **Проверка:** на устройстве с включённым VPN-клиентом откройте `https://2ip.ru` —
IP должен совпадать с сервером, `ping` до сервера должен идти через VPN-интерфейс
(`ip route` покажет маршрут по умолчанию через `wg0`/`awg0`).

## Обновление и обслуживание

Для SOCKS5-варианта (Docker) обслуживания почти нет:

```bash
docker pull serjs/go-socks5-proxy
docker stop socks5-proxy && docker rm socks5-proxy
# и заново команда docker run из Шага 3 с теми же переменными
```

Раз в несколько месяцев стоит **сменить пароль** прокси (та же команда `docker run`
с новым `PROXY_PASSWORD` после остановки/удаления старого контейнера) — особенно
если он когда-либо мог "засветиться" (например, был скопирован в чат/скриншот).

Для WireGuard/AmneziaWG — обновление пакета через `apt upgrade`, конфиги клиентов
менять не требуется.

## Бэкап настроек прокси

Настроек тут немного, но потерять их обидно. Минимум — сохраните себе отдельно (не
только на сервере) команду запуска с реальным паролем и, если использовали WireGuard,
файлы конфигов клиентов:

```bash
# Простая выгрузка конфигурации контейнера для памяти
docker inspect socks5-proxy > /root/backups/socks5-proxy-config.json
```

Если сервер общий с основной методичкой — эти файлы можно добавить в тот же
`backup.sh` из [основной методички](README.md#бэкапы--конкретный-скрипт).

## Проблемы, с которыми реально столкнулись (актуально и здесь)

Все пункты ниже — из практики эксплуатации именно таких прокси/VPN-сервисов на VPS:

- **Firewall теряет правила после перезагрузки сервера** — тот же баг `ufw`, что и в
  основной методичке: конфиг на диске полный, а реально загруженные правила иногда
  меньше после ребута. Симптом: прокси "внезапно" недоступен снаружи, хотя локально
  всё работает. Лечится вручную `ufw reload`, а насовсем — systemd-юнитом, который
  делает `ufw reload` при каждой загрузке (см. основную методичку, раздел Шаг 3).
- **Голый SOCKS5/WireGuard в некоторых сетях может резаться DPI** — если после
  настройки прокси доступ всё равно не работает, а сервер точно жив и порт открыт,
  проблема может быть на стороне провайдера/сети, блокирующей сам протокол, а не в
  настройке. В этом случае помогает вариант с маскировкой (AmneziaWG, Hysteria2,
  VLESS+TLS через xray) — они прячут VPN-трафик под обычный HTTPS-трафик.
- **Один и тот же порт/IP на несколько разных VPN-протоколов сразу — источник путаницы.**
  Если на сервере уже что-то слушает нужный порт (например, уже стоит другой VPN),
  не переиспользуйте порт бездумно — заведите каждому сервису свой отдельный порт.
- **Не забывайте про пароль на прокси.** Прокси без аутентификации, торчащий на
  публичном IP, находят автоматическим сканированием за часы, а не дни — его начинают
  использовать посторонние, съедая ваш канал и репутацию IP.

## Частые вопросы

**Это дешевле, чем вариант с Claude Code?**
Да — не нужен домен, не нужен SSL-сертификат, тариф сервера может быть минимальным.
Практически весь курс — это фактически стоимость самого дешёвого VPS, от ~200 ₽/мес.

**А это тот же риск блокировки аккаунта, что и с Claude Code?**
Логика та же: свой личный, не шэренный IP снижает вероятность автоматических
ограничений по сравнению с публичным VPN-сервисом, но официальной гарантии это не
даёт. Официальные условия — [Usage Policy](https://www.anthropic.com/legal/aup) и
[Consumer Terms](https://www.anthropic.com/legal/consumer-terms) — проверьте сами,
не полагайтесь только на пересказ здесь.

**Можно совместить с основной методичкой на одном сервере?**
Да, никаких противоречий — просто на одном сервере будет и Claude Code с панелью
(доступ по домену), и SOCKS5-прокси на отдельном порту (для обычного браузера).
Главное — не забыть открыть в firewall оба порта, и не путать, какой для чего.

**Нужно ли мне разбираться в Docker, чтобы поднять SOCKS5-прокси?**
Нет, команда из Шага 3 выше — единственное, что нужно ввести. Если Docker ещё не
установлен на сервере, попросите Claude Code установить его первым шагом.
